# Portfolio 客户偏好学习接入进度

2026 年 11 月 17 日。基于本地 latest-main 的 eda2f1c，工作分支为 feature/portfolio-preference-integration。

## 本轮完成的范围

项目已纳入队友交付的学习模块和本地接入修正。学习模块负责解析、证据加权、状态保存和重建。Portfolio A 负责采集真实操作、跟踪投递和读取该客户的上下文。启用模块前，应用会保存客户操作并显示待处理状态。

- 直接计算和自然语言模式共用页面客户选择。默认提问改为“当前所选客户”，避免切换客户后仍引用 Garcia。
- 绑定客户的自然语言请求进入 A 时携带该客户上下文；工具调用若试图访问另一客户，后台会返回身份冲突。原话明确出现其他已有客户的完整名称、客户编号或账户编号时，保存前提示核对；编号与中文紧邻时也会检查。昵称、代词等复杂指代仍需要顾问选对客户及解析模块判断。
- 采集事件编号、同一轮分析的来源组、原话、文本来源、参数及字段来源、执行结果、当前持仓比较基础。手动输入 60 与沿用默认 60 可以区分。
- 接收与完成使用同一个事件编号的两个修订。网络中断后原输入重试沿用编号；用户收到结果后再次运行是新操作，仍属于当前分析组。新建组只表示新的操作上下文，不自动证明证据独立。
- 本地 SQLite 操作队列保留历史，重复事件不重复入队，同号不同内容拒绝。同一编号仍在运行时，后来的并发重试会得到提示，不重复启动模型。最终运行结果与完成修订一起提交；重试读取已保存结果时重新查询当前投递状态。
- 尚未处理的接收修订由完成修订替代，原始历史保留。已经处理的接收修订则交给模块按同事件新修订替换贡献。旧版队列也会按这条规则整理，避免初始解析失败挡住含完整结果的新修订。
- 撤回是追加记录，原始数据保留。同一事件尚未处理的修订先被撤回替代，撤回优先于普通记录投递，避免一条失败的解析挡住撤回。待撤回尚未处理时暂停向 A 提供旧画像；即使计算在撤回后才返回，迟到的修订也不会重新投递给学习模块。
- 页面新增客户说明、近期记录、处理状态、输入来源、更新结果、撤回及导出。模块返回上下文后，按团队明确说明、暂定倾向、近期关注、未知项和使用说明展示。
- 普通计算数字仍来自原工具；模型及偏好模块不会改写计算参数。学习存储故障单独报告，直接计算结果仍可查看。

## 分工调整

以最新的完整队友说明为准：队友交付的模块自行保存学习历史和客户状态；本轮新增 SQLite 保存应用侧原始事件与投递状态。两者用途不同，应用侧不再另写一套贝叶斯算法或客户状态数据库。

当前已有的三条 DEMO 输入继续作为队友的开发基准。本应用真实使用已有 CLI 客户编号，当前持仓来自实际工具返回；不会为了复现 DEMO 中的 80/20 而伪造持仓。

## 现在如何试用

打开 http://127.0.0.1:8002，进入 Portfolio Analysis。

1. 选 Garcia 或其他客户，不填股票目标，运行计算。展开近期记录，可看到默认目标及真实比较基础。
2. 手动输入 60，再运行；数值可以相同，但来源应为 manual。
3. 在“补充客户说明”填写该客户的需求并保存。模块和 Gemini 均已配置时，检查解读结果及原话来源。模型连接缺失时，说明会保存为待解析。
4. 切换客户，确认说明和操作不会跟过去；自然语言模式也应继续显示当前客户。
5. 撤回一条记录。没有模块时显示“撤回待处理”，而非伪称画像已经重建。
6. 导出当前客户记录。再次打开网页或重启预览后，仍能读取历史。

“开始新一轮分析”用于明确区分新的操作上下文；当前页面内的连续试算沿用同一组。刷新网页会开始新组，学习模块仍需自行判断跨组相关性。

## 队友模块接入约定

仅从本地可信配置加载模块，不接收网页传来的模块名称或路径。设置环境变量后重启服务：

```text
SIA_PORTFOLIO_LEARNER_FACTORY=self_improving_ai.agents.portfolio.preference_learning.adapter:create_adapter
SIA_PORTFOLIO_LEARNING_DIR=<应用侧学习数据目录，可选>
```

工厂接收 `workspace_dir`，再以模块支持的 `work_dir` 创建 PortfolioLearner。模块保存在学习目录的 learner 子目录。启用后，解析器使用 Portfolio A 的 Gemini 配置。配置缺失时，含原话的记录保留待解析状态。可以先在一个独立的 SIA_PORTFOLIO_LEARNING_DIR 中验收新规则版本。

同一事件从接收到完成时，如果原话、范围和来源都匹配，完成修订会复用首次已经通过校验的文本解析。计算相关证据仍用完成修订的结果重新生成。导出中的 `extraction.parser.reused_from_revision` 可核对来源。首次解析未完成，或原话、范围有变化时，会尝试新的解析。

| 方法 | 约定 |
|---|---|
| process_event(event: dict) | 接收完整事件修订。返回整体状态和已保存的解析状态。重复提交的记录如果仍在待解析或部分解析，继续标为待处理。 |
| retry_event(event: dict) | “重试待处理记录”通过此方法重新解析最新待处理修订。成功后用同一事件 ID 和修订更新保存结果，已解析记录重复投递时直接返回已保存状态。 |
| get_context(client_id, scope) | 返回包含同一 client_id 的 LearningContext 字典。字段按样例中的 summary、team_declared、tentative_preferences、recent_attention、unknowns、usage_notes 输出。当前页面主要使用客户通用范围。 |
| retract_event(client_id, event_id) | 撤回该客户该事件的贡献并重建。应用已验证事件归属，模块会保存撤回标记，即使尚未收到原记录。重复撤回可安全重试，迟到的原记录会被拒绝。 |

如果模块返回 `{update_result, learning_context}` 的样例外壳，桥接层提取 update_result 的 status 作为投递确认，并在 get_context 返回 learning_context。模块内部方法或构造参数不同，只改桥接层。

模块按客户、事件和修订去重。待解析或部分解析的更新仍可重试，页面会保留这次失败的解析状态。无法确认的纠正和无法绑定的范围会显示“需人工确认”，后续有效事件可以继续处理。分析工具失败后，顾问输入的原话仍可解析或重试。失败的计算结果不会产生试算方向证据。

自然语言和客户说明接口可以提交可选的 `account_id`。A 先验证账户归属，再把已经核实的编号传给解析器。账户范围仅应用于该账户。自然语言请求绑定账户后，该请求的账户计算工具也必须使用同一账户。

规则版本 `portfolio-preference-v0.1` 在每个范围与偏好维度内，对独立来源的默认试算最多采用最近五组。五组是原型设定，由 `max_default_groups_per_scope` 控制。其他试算仍保留历史。同组最强信号规则、手动试算和明确声明的原有权重继续适用。已有旧规则的学习数据库需要显式重放才能采用新规则。

模块调用在独立后台线程内串行执行，网页最多等待约一秒就返回当前处理状态；单批投递也有时间预算。超过等待时间时后台调用可以继续，应用不会同时发起另一次模块调用，也不读取可能正在修改的画像。原始记录仍可保存、查看和撤回，正常计算仍可返回。后台完成后可刷新读取结果；未送出的记录由下一次操作或手动重试继续处理。线程无法强行终止模块内部的死循环，因此模块仍必须实现自身模型请求超时；永久卡住时需要修复模块并重启本地服务。应用不会把异常文本里的凭据或请求详情显示给用户。

模块返回的上下文必须属于请求客户和范围，summary 必须是字符串，展示列表必须采用约定的结构。错误、待处理、客户或范围不符的上下文不会传给 A。读取页面失败时清除旧画像，避免显示上一次的过时内容。页面最近记录按操作组织，始终携带该操作的撤回标记；完整导出保留全部修订。

本轮为单进程本地部署，使用一个 Uvicorn worker。没有实现多进程分布式投递锁、后台自动重试、自动规则迁移；不要直接把服务扩为多 worker。更换模块数据目录或规则时要另做显式迁移，不能把已有投递确认当作新模块已收到历史。

额外事件字段 `text_source` 标明原话是预填、手动还是未知；自然语言完成修订中的 `execution_trace` 只记录执行证据，其中的模型生成参数不能当作顾问新选择。未提供足够背景的字段保留为空，不推测上一轮配置。event_id 不代表证据独立，evidence_group_id 保留共同来源。

## 代码入口

- agents/portfolio/application.py：真实顾问输入的共用服务，计算、自然语言和客户说明都从这里进入。
- agents/portfolio/learning.py：应用侧事件日志、模块连接、投递、撤回和上下文隔离。
- dashboard/portfolio.py：网页 API。
- dashboard/src/CustomerLearning.jsx：客户信息和学习记录展示。

原有 C 通过 AgentTool 调用 A 的路径保留。A 的共用工具新增 get_client_learning_context，可按解析出的客户读取信息；C 转述文本不会被自动当成新的顾问证据。要从 B/C 写入学习事件，还需传递原始顾问文本、明确客户和原始来源编号，再调用 application 层；这部分尚未完整接通。本轮没有改 B 的会议处理或 C 的记忆算法。

## 验证范围与后续对接

队友原有 27 项测试在修正版本上通过。修正后另有 75 项项目后台与计算检查、15 项浏览器检查通过。项目后台报告保存为 artifacts/delivered-learning-checks.xml。后台检查使用本机模拟数据库和独立的学习数据目录。浏览器检查使用独立服务和 browser-learning 目录。现有 SDK 有弃用提示。

已检查客户隔离、原话身份冲突、默认与手动参数、重复请求与冲突、保存读取、投递失败、撤回与迟到结果、上下文实际进入 ADK 指令，以及原有计算回归。网页检查覆盖记录、说明、撤回、导出、客户切换、自然语言请求字段、移动端和已有页面功能。

验证真实 ADK 调用链时使用明确标注的脚本模型；学习接口检查使用 ContractDouble。它们只证明数据传递和控制逻辑，不证明真实语言理解、偏好学习效果或投资结果。当前没有使用客户凭据调用外部模型。

脚本模型覆盖了同一请求在记录偏好前、写入后和撤回后三次运行。这三次的工具结果一致，客户说明只在写入后进入模型上下文。本机 Gemini 连接目前未配置，真实模型的语义解析仍待验证。

## 客户级本地验收

验收使用独立的 `data/portfolio-learning-solo-acceptance` 目录。重复解析修复后，27 项交付测试和 78 项项目后台检查通过。在实际 A 执行器上，用固定解析和脚本模型记录了学习前、学习后及撤回后三次工具调用和客户上下文。证据保存在 `artifacts/portfolio-solo-acceptance.json`，后台结果保存在 `artifacts/portfolio-solo-checks.xml`。

从 `local-preview/latest-main` 目录启动同一验收环境时，在当前 PowerShell 窗口使用以下配置。重新打开 PowerShell 后需要重新设置。

```powershell
.\Stop-Local.ps1
$env:SIA_PORTFOLIO_LEARNER_FACTORY = 'self_improving_ai.agents.portfolio.preference_learning.adapter:create_adapter'
$env:SIA_PORTFOLIO_LEARNING_DIR = Join-Path (Get-Location) 'data/portfolio-learning-solo-acceptance'
.\Start-Local.ps1
```

真实模型验收先在 **Portfolio Analysis → Connections → Portfolio Agent** 使用 **Test Gemini**，通过后执行 **Save connection**。用单独的模拟客户和数据目录完成以下检查。

| 场景 | 通过条件 |
|---|---|
| 同一组合分别使用预填和手动 60/40 | 工具结果一致，记录分别标记默认和手动来源。 |
| 先分析，再保存“这个客户整体比较保守”，重复同一个问题 | 第二次 A 解释时可追溯到该说明，工具仍按本次指定的参数计算。 |
| 测试“假设这个客户比较保守”和“这个客户不算保守” | 两条输入均不作为确认的保守说明。 |
| 切换客户并重新启动 | 第二位客户看不到这条说明，原客户状态可恢复。 |
| 撤回保守说明并重复同一个问题 | A 的上下文和回答停止引用该说明，历史显示已撤回。 |

这些结果用来判断真实模型对输入的解释是否符合预期。当前实现可在客户级使用；同一轮分析中的临时偏好仍缺少 A 的分析编号传递。网页账户选择入口、B/C 自动写入和默认试算权重校准取决于后续验收范围。
